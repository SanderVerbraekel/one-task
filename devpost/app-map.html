One Task

One task on screen. The rest stay hidden in this browser. Pressing “Task finished” moves the focus score, then the next task appears.

Run it again from the project folder with python -m http.server 8765, then open http://127.0.0.1:8765/. This map describes commit ae74a3f. It is a snapshot and can drift if the code changes.

Press “Task finished”

This route is a reference. It was not walked in the editor.

  1. The button

    index.html — #finish-task

    The press starts in the task card. Nothing else on the page is a list of tasks.

  2. The clock and the save

    app.js — finishTask, then persist

    finishTask measures the gap from shownAt to now with Date.now(), rounds it to the nearest minute, and writes the pool back to localStorage under the key one-task.

  3. The new score and the next task

    app.js — scoreAfterFinish, pickTask, render, placeFocusMarker

    Each minute under the estimate adds 2 points. Each minute over subtracts 2. The score stays between 1 and 100. pickTask chooses the next task, and placeFocusMarker moves the gauge to the new number.

To change this, start here

  • Score math: scoreAfterFinish in app.js.
  • Which task appears: pickTask and effortForScore in app.js.
  • The words on the card: #task-detail and the “Your task” label in index.html.
  • Where the gauge marker sits: placeFocusMarker in app.js.
  • What survives a reload: load, persist, and STORAGE_KEY in app.js.

A practice to reuse

spec.md → Decisions and Open Issues chose localStorage and Date.now(), and not a database or a timer library, because the page only has to remember one pool and two times.

The check was concrete. scoreAfterFinish(50, 10, 15) returns 40. On the page, finishing a 1-minute task at focus 80 showed 82, then a task of the other effort.

On another project, name the job first, pick the smallest tool that does that job, and check one result you can see.
